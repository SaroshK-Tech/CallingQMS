1. PROJECT SUMMARY (for proposal intro / executive summary)
================================================================================
AlgoriSync EQMS is a complete, self-hosted Electronic Queue Management System
that digitizes the full customer journey:

  Customer takes a ticket at the Kiosk  ->  waits  ->  is called to one or more
  counters (in a service path)  ->  completes service  ->  leaves.

Implementation is a real-time web application built on Django + Django Channels
(WebSocket). No page refreshes anywhere — kiosk tickets, counter calls, display
boards and audio announcements all update instantly across every screen on the
network the moment an action happens.

The system runs on a single Windows PC on the local network (server host). All
client screens (kiosk, display boards, counter stations) are just browsers on
any device — no client software installation required.

Key differentiators over off-the-shelf systems:
  - Multi-counter / multi-stage service PATH (ticket flows through counters in
    a defined sequence, e.g. Check-in -> Documents -> Payment -> Token).
  - Auto silent thermal receipt printing from the kiosk (no print dialog).
  - Human-like multilingual audio calling (English + Urdu) with real neural
    voices, parametrically generated so new counters/series never need manual
    audio work.
  - Commercial advertising on the display board (1/4 live calls : 3/4 ads).
  - LAN-ready: works from any IP without reconfiguration.

2. SCOPE OF WORK — ITEMIZED MODULES (use 1 line-item each in the quotation)
================================================================================
ITEM 1  — Kiosk Ticket-Generation Screen
  - Public brand screen with company logo (AlgoriSync logo supplied).
  - Single big button (touch-friendly) -> generates next ticket.
  - Multi-service option: user selects service type (A, B, VIP, etc.); ticket
    numbers auto-increment per service per day (A001, A002 ... B001 ...).
  - Silent auto-print of a thermal receipt with NO print dialog / confirmation
    (uses default thermal printer).
  - Receipt contents: AlgoriSync logo, "Electronic Queue Management System",
    Ticket Number large & bold (e.g. A001), "Please Wait For Your Turn",
    print date/time.
  - Rationale handling: repeated prints, blank clicks ignored, per-day number
    reset automatically.

ITEM 2  — Full Display Board (1:3 Calls:Ads split)
  - One screen, ratio 1:3: left 1 column = recent call cards, right 3 columns =
    advertising (video / slide-show images).
  - Live updates over WebSocket — no refresh; every new call appears instantly.
  - Supports background/overlay ad rotation with configurable order.
  - Shows: ticket number, counter name, service, time called, status styling.

ITEM 3  — Single Counter Waiting-Area Display
  - Per-counter wall display (e.g. "Counter 1" screen) showing the currently
    called ticket number in large type for that counter's waiting area.
  - Live update independent of the main board.

ITEM 4  — Counter Dashboard (operators)
  - Password-protected login per counter user (accounts).
  - Live list of today's waiting tickets (all services for that counter).
  - Actions per ticket: CALL, RECALL, DONE / complete, NEXT ticket,
    PREVIOUS ticket (repeats last called ticket).
  - Operator can pick ANY waiting ticket, not just the next one.
  - Every call/recall triggers: screen updates on all boards + audio
    announcement automatically.
  - Same-day scope only: waiting lists and next/prev selection show ONLY today's
    tickets, regardless of status.

ITEM 5  — Travel / Service-Path Logic (counter sequencing)
  - Ticket moves through counters in a configurable sequence per service
    (CounterService ordering).
  - "DONE" at one counter releases/queues the ticket for the next counter in
    the path (or completes the journey at the final counter).

ITEM 6  — Real-time Engine (WebSockets)
  - Django Channels / Daphne ASGI server for sub-second pub/sub.
  - Channel groups: dashboard_{counter}, display_board (all screens),
    counter_display_{id}.
  - All-connected-clients broadcast: ticket created, called, recalled, served.
  - No refresh required anywhere.

ITEM 7  — Audio Announcement System (English + Urdu)
  - "Ticket # A 001, Please proceed to Counter 1" + Urdu equivalent.
  - REAL neural TTS (not Windows voices): English via gTTS, Urdu via
    edge-tts ur-PK-UzmaNeural (accents preserved).
  - Parametric generation: audio files generated automatically when counters or
    service prefixes (A/B/VIP) change — no manual voice recording/editing ever.
  - Server-side playback (fires on call) + browser-based playback on boards.

ITEM 8  — Administration (Django Admin)
  - Manage Services (name + prefix + active), Counters, CounterService
    sequencing, CounterUser assignments, Tickets, TicketCall audit log
    (full call history incl. recalls/serves), Advertisements (image/video).
  - Auto-regenerates counter audio on save when counter name changes.
  - Full audit trail of every call/recall/completion.

ITEM 9  — Backend & Architecture
  - Framework: Django 6.1 + Channels 4.3 (ASGI), Daphne server.
  - Database: SQLite for single-host deployment (swappable to PostgreSQL/MySQL).
  - WhiteNoise serves static files under Daphne.
  - Environment-variable configuration (secret key, debug, allowed hosts,
    CSRF trust, DB path) for safe production deployment.
  - Clean app structure: core (models/admin), accounts, kiosk, counter, display.

ITEM 10 — Deployment & Delivery
  - Ready-made launchers (.bat) for server host and client machines.
    * start_server_on_host.bat — starts server, auto-detects LAN IP, prints URLs.
    * kiosk.bat / deploy_kiosk.bat — client kiosk PCs; remembers server IP
      (kiosk_config.txt), opens kiosk in fullscreen mode (Chrome/Edge).
    * kiosk_display.bat — client display screen launcher.
  - Runs on ANY IP on the LAN without reconfiguration (relative URLs +
    bind 0.0.0.0).
  - Documentation, default credentials, and setup guide included.

ITEM 11 — Recurring Support / Maintenance (optional add-on)
  - Server & software updates, TTS regeneration, data backups, admin of new
    counters/services/ads, phone/remote support (term to be agreed).

4. TECHNICAL SPECIFICATIONS (for proposal "Technical Approach")
================================================================================
Backend:     Django 6.1.1, Channels 4.3.2, Daphne 4.2.3 (ASGI), asgiref
Database:    SQLite (dev/single-host) — swappable PostgreSQL/MySQL
Frontend:    Vanilla HTML/CSS/JS + WebSocket clients (no heavy framework =
             lightweight, fast on cheap kiosk PCs)
Static:      WhiteNoise (no Nginx needed on LAN)
Audio:       gTTS (English), edge-tts ur-PK-UzmaNeural (Urdu), ffmpeg trimming,
             admin-triggered auto-regeneration
WebSocket:   Groups: dashboard_{counter_id}, display_board,
             counter_display_{counter_id}
Models:      Service, Counter, CounterService, CounterUser, Ticket
             (WAITING/CALLED/IN_PROGRESS/COMPLETED/CANCELLED), TicketCall,
             Advertisement
Deployment:  Single Windows host, bind 0.0.0.0, port 8000 (configurable), no
             client install — browsers only
Security:    Auth via Django auth, CSRF, env-var secrets, ALLOWED_HOSTS control
